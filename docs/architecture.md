# WorkLens v0.1 架构决策

日期：2026-09-08。基于当前 `prd.md`；不修改用户已有的 PRD。

## Pi 集成与版本（需求 010、040—056、061—063）

npm 当次查询的最新版本为 `@earendil-works/pi-coding-agent@0.85.1`，并固定同版本 `pi-ai`、`pi-agent-core`。实际发布包比本地参考克隆存在小幅接口差异：发布包包含 `max` 推理等级，压缩事件为 `compaction_start/end`。实现与类型检查以安装包的公开导出为准。

`ModelRuntime` 为应用级共享实例，服务商、认证方式、模型、可用性和推理等级来自它及 `getSupportedThinkingLevels()`。不维护服务商白名单，不实现任何模型 HTTP 协议。文本目录为空的 provider 不进入设置页。缓存采用公开 `ModelsStore` 契约保存到 `userData/model-cache`；显式网络刷新带 15 秒取消信号，保留既有目录。

每个会话通过唯一的 `createAgentSession()` 运行。`Map<conversationId, Runtime>` 持有会话；同会话的创建、切换模型和删除串行，不同会话没有全局运行锁。发送请求有独立去重标识，每次运行使用 UUID。所有事件携带会话 ID、运行 ID、序号及有界派生视图；约 40 毫秒合并更新。

## 目录与发现（需求 020—021、062）

所有会话显式注入相同 `runtimeCwd`、`sessionDir`、`agentDir`，打开历史时使用 Pi 公开的 `cwdOverride`。开发与测试数据和正式数据隔离。

使用 `SettingsManager.inMemory()` 与 `DefaultResourceLoader`，关闭扩展、技能、模板、主题、上下文文件发现；显式设置系统提示词及空的附加提示词。不会加载用户的 Pi 全局配置或项目 AGENTS/CLAUDE 文件。

## 工具与取消（需求 050—056）

Windows 使用 PowerShell，macOS 使用 Bash。文件工具均来自 Pi 公开工厂。`write/edit` 只追加确认说明并做调用调度，参数校验、文件操作与返回结果仍由 Pi 完成。`write/edit/Shell` 使用 Pi 的 `executionMode: sequential` 元数据。

Shell 使用公开的本地 operations 工厂执行，适配层只把实际退出码补入结果 details 供时间线恢复；不另写进程或取消实现。命令初始目录和超时设置同时显示，Pi 返回的超时和非零退出诊断分别呈现。

文件调度器按真实路径（含已存在的父路径）规范化，Windows 使用不区分大小写的键。同一文件等待支持 AbortSignal，可立即移出队列；不同路径和会话的 Shell 保持并发。此调度器不是权限策略或目录限制。

停止针对指定 AgentSession 调用 `abort()`，等待模型与工具收束。关闭窗口及退出应用遍历取消全部任务；macOS 关闭窗口时也取消任务，重新打开后仍可使用服务。

## 持久化与崩溃（需求 030—034、063、11.5）

Pi JSONL 是唯一聊天历史源。列表、解析、恢复、压缩及原生迁移全部经 `SessionManager`，不实现 JSONL 修复器。

界面从 `SessionManager.getBranch()` 读取完整分支，而不是把压缩后的模型上下文当成聊天历史；压缩摘要留在对应时间位置，早期消息仍可查看。工具开始时间和耗时通过 Pi 公开的 `appendCustomEntry()` 写入 `worklens.tool-timing` 条目，重启后随工具调用恢复，不进入模型上下文。

源码及实测确认：Pi 首个助手消息结束前不落盘，用户提交后存在崩溃窗口。因此主进程在接受请求后、开始运行前，原子写入一个 `runs/<runId>.pending.json` 恢复记录，保存本次待执行输入和模型选择；正常落盘收束后删除。它不是长期消息数据库，也不会重复写入完整历史。下次启动只将未完成请求提供为可检查的草稿，不自动重放。

工具开始和结束同步写入仅含会话 ID、运行 ID、工具 ID、工具名及时间的运行日志，不记录参数、文件内容或秘密。Pi 在助手消息结束后持久化工具调用，工具结果结束后持久化结果；日志补充中断定位，不能撤销已发生的外部副作用。

删除会话先取消该会话、解析真实路径、校验目录及文件内 ID，再删除单个文件，不递归删除数据根目录。

## 凭据和 IPC（需求 012、047、060—063）

`CredentialStore.modify/delete` 按 provider 串行。每家凭据单独进行系统加密和原子替换，避免其他服务商写入相互覆盖。系统加密不可用时拒绝持久化，不降级明文。OAuth 更新仍由 Pi 管理并走同一个存储契约。

损坏或不可解密的凭据按 Pi 允许的尽力读取契约返回未配置状态，同时在对应服务商下显示脱敏诊断。读取不修改原文件，也不自动创建替代凭据；用户明确重新配置或移除后才更新文件，避免出现“提示重新配置，但保存新凭据也被坏文件阻断”的死循环。

预加载桥仅提供列举的业务请求。主进程校验请求 schema、窗口和主 frame；关闭 Node integration、开启 sandbox 和 context isolation，禁止窗口打开、导航及网页权限申请。外链只允许无 URL 用户凭据的 HTTP(S)。渲染进程没有任意文件、目录或命令入口。

界面由 Pi 数据提取文本与工具摘要，隐藏已知凭据。Markdown 不启用原始 HTML 执行，图片仅显示占位文字，避免模型回复导致远程图片请求。全部模型网络请求位于主进程。

脱敏按 DTO 字符串值递归处理，保留字段名、数字、布尔值和空值；同时覆盖凭据在工具参数 JSON 中的转义形式，避免对完整序列化 JSON 替换而破坏事件结构。

## 发布边界

本机可以验证 Windows 开发与 ASAR 产物，无法据此声称 macOS、干净机器安装、签名公证或真实云端账户矩阵已通过。所有 provider 均保持“WorkLens 尚未实测”标签，单次连接成功也不升级产品验证标签。
